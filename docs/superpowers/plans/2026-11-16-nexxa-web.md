# NEXXA Web (แอดมิน + แดชบอร์ดสาธารณะ + 3D) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** เว็บของ NEXXA: หน้า login แอดมิน + CRUD (สถานี, ชนิดผัก, ล็อตผัก, API key AI, device key, การตั้งค่า AI, ผู้ดูแล) + แดชบอร์ด/กราฟสาธารณะ (ไม่ต้อง login) + โมเดลโรงเรือน 3 มิติ + ข้อมูลตัวอย่าง 100 วัน

**Architecture:** เพิ่มแพ็กเกจ `server/app/web/` ใน FastAPI เดิม: หน้าสร้างด้วย Jinja2 ฝั่งเซิร์ฟเวอร์ + JavaScript ธรรมดา (ES modules) + three.js และ Chart.js ที่เก็บไว้ใน `static/vendor/` (ไม่พึ่ง CDN ตอนรัน) ความลับเข้ารหัสด้วย Fernet ผู้ใช้แอดมินเก็บรหัสผ่านแบบ scrypt session เป็นคุกกี้ลงลายมือชื่อ API สาธารณะอ่านอย่างเดียวคืนเฉพาะข้อมูลสรุป

**Tech Stack:** FastAPI, Jinja2 (ใหม่), cryptography (ใหม่), SQLAlchemy 2, pytest, Chart.js และ three.js (vendored, ปักเวอร์ชัน), JS ธรรมดา

**Spec:** `docs/2026-11-16-nexxa-web-design.md`; ระบบดีไซน์ `design-system/nexxa/MASTER.md` (ต้องอ่านก่อนทำหน้าใด ๆ); โค้ดเดิมบนสาขา `feat/server-pipeline`

## Global Constraints

- ห้ามมีความลับ/API key ในโค้ด เทสต์ ล็อก audit log หน้า HTML หรือคำตอบ API; หน้าเว็บแสดง key ได้แค่ 4 ตัวท้ายกับวันที่เพิ่ม
- key ของ AI ในฐานข้อมูลเข้ารหัส Fernet ด้วย env `NEXXA_SECRET_KEY`; ถ้าไม่ตั้ง → หน้าจัดการ key ถูกปิด (แสดงเหตุผล) และห้ามเขียน key แบบอ่านออกลงฐานข้อมูล
- device key เก็บเป็นแฮช (SHA-256 ของค่าที่สุ่มด้วย `secrets.token_urlsafe(32)`) และแสดงค่าจริงครั้งเดียวตอนสร้าง; env `NEXXA_DEVICE_KEY` เดิมยังใช้ได้เป็น fallback; เปรียบเทียบด้วย `hmac.compare_digest`; fail closed ถ้าไม่มีทั้งสองแบบ
- รหัสผ่านแฮชด้วย `hashlib.scrypt` (stdlib) พร้อมเกลือสุ่มและพารามิเตอร์เก็บในสตริงแฮช; คุกกี้ session `HttpOnly`, `SameSite=Lax`, `Secure` เมื่อคำขอเป็น HTTPS, มีวันหมดอายุ, ลงลายมือชื่อด้วย HMAC (ความลับจาก `NEXXA_SESSION_SECRET` หรือสืบจาก `NEXXA_SECRET_KEY`; ไม่มีทั้งสอง → ปิด login พร้อมข้อความชัดเจน ไม่ใช้ค่าเริ่มต้นที่เดาได้)
- ทุกคำขอที่เปลี่ยนข้อมูล (POST/PUT/DELETE) ของหน้าแอดมินต้องมี CSRF token ที่ตรงกับ session; ตัวนำทางหลัง login (`next`) ต้องเป็นพาธภายในไซต์เท่านั้น (กัน open redirect); จำกัดจำนวนครั้ง login ผิด (เช่น 5 ครั้ง/15 นาที ต่อ IP+ชื่อผู้ใช้) — `shortcut: ตัวนับในหน่วยความจำ, ใช้ฐานข้อมูลเมื่อรันหลายโปรเซส`
- Jinja2 เปิด autoescape ทุกแม่แบบ; ข้อความจากผู้ใช้ที่ไปโผล่ใน JavaScript (ชื่อสถานี ฯลฯ) ใส่ผ่าน `textContent`/JSON เท่านั้น ห้าม `innerHTML` กับข้อมูลผู้ใช้
- API สาธารณะ `/api/public/*` อ่านอย่างเดียว คืนเฉพาะตัวเลขสรุป สถานะ ชื่อสถานี/ผัก ลำดับ/ตำแหน่งแผนผัง **ห้าม**: รูปภาพ/พาธไฟล์ภาพ, `note` ดิบ, `rfid_uid`, key, ข้อมูลผู้ดูแล; ภาพดูได้เฉพาะเมื่อ login
- ห้ามลบผู้ดูแลคนสุดท้าย; การลบ/แก้ทุกอย่างบันทึก `audit_log` (ใคร/อะไร/เมื่อไร — ไม่บันทึกค่าความลับ)
- **ธีม (เปลี่ยนตามคำขอผู้ใช้ 2026-11-16 พร้อมภาพอ้างอิง):** สไตล์ "ใบไม้เขียว + กระจกฝ้า (frosted glass)": พื้นหลังภาพใบไม้เบลอสีเขียว, การ์ดโปร่งแสงเบลอ มุมโค้ง 16–24px, หน้า login เป็นการ์ดแบ่งสองฝั่ง (ซ้าย: ภาพใบไม้พร้อมโลโก้เส้นขาว, ขวา: ฟอร์ม "ยินดีต้อนรับ" ช่องกรอกทรงมนมีไอคอนนำหน้า ปุ่มไล่เฉดเขียวซาจ), **ใช้ธีมเดียวกันทั้งเว็บ** (login, แอดมิน, แดชบอร์ด, กราฟ, 3 มิติ) และ**มีโหมดสว่าง/มืด** สลับได้ จำค่าไว้ (localStorage) และตามค่าระบบ (`prefers-color-scheme`) เมื่อยังไม่เคยเลือก; ใช้โทเคนจาก `design-system/nexxa-nature/MASTER.md` (สไตล์ Organic Biophilic; primary #15803D, ฟอนต์ Plus Jakarta Sans + Noto Sans Thai fallback — ไม่ใช้ Fira ที่ MASTER แนะนำเพราะไม่มีตัวอักษรไทย) และมี `design-system/nexxa/MASTER.md` เดิมเป็นเอกสารเก่าเท่านั้น; ห้ามคัดลอกงานออกแบบหรือโลโก้ของภาพอ้างอิง (ออกแบบโลโก้/ภาพใหม่เอง); คอนทราสต์ ≥ 4.5:1 **ทั้งสองโหมด** (ปุ่มเขียวซาจอ่อนในภาพอ้างอิงตัวหนังสือขาวจะคอนทราสต์ต่ำ → ใช้เขียวเข้มกว่าแต่คงบรรยากาศเดียวกัน); ไม่มีแฟลชสลับธีมตอนโหลด (สคริปต์ตั้งธีมเป็นไฟล์ภายนอกโหลดใน `<head>` ไม่ใช้ inline); กราฟ (Chart.js) และฉาก 3 มิติต้องเปลี่ยนสีตามโหมด; รูปพื้นหลังใบไม้ต้องมีใบอนุญาตใช้ได้ (CC0/Public Domain/ใบอนุญาตเปิด ที่ระบุใน `static/img/CREDITS.md`) หรือสร้างเอง (SVG/CSS) และเป็นไฟล์ที่เบา (WebP/AVIF ≤ ~200 KB ต่อไฟล์ พร้อม `loading`/ขนาดที่เหมาะสม)

  - `security.hash_device_key(key: str) -> str` (SHA-256 hex), `security.new_device_key() -> str`
  - `python -m app.create_admin --username U` อ่านรหัสผ่านจาก prompt แบบไม่แสดงตัวอักษร (หรือ env `NEXXA_ADMIN_PASSWORD` สำหรับสคริปต์) สร้าง/อัปเดตผู้ดูแลและพิมพ์ผล (ไม่พิมพ์รหัสผ่าน); ฟังก์ชันที่ทดสอบได้: `create_admin.create_or_update(session, username, password) -> AdminUser` (รหัสผ่านสั้นกว่า 10 ตัวอักษรถูกปฏิเสธด้วย `ValueError`)
