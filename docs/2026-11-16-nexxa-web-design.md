# NEXXA Web (แอดมิน + แดชบอร์ดสาธารณะ) — Design (ร่าง รออนุมัติ)

ต่อยอดจาก `docs/2026-11-15-nexxa-design.md` และโค้ดบนสาขา `feat/server-pipeline`
ป้าย **[คุณเลือก]** = ผู้ใช้สั่ง, **[ผมเลือก]** = ข้อเสนอของผู้ช่วย (แก้ได้)

## 1. เจตนาและเหตุผล
ให้ผู้ปลูกใช้ระบบผ่านเว็บ: จัดการค่าต่าง ๆ เองโดยไม่ต้องแก้ไฟล์/ตัวแปรบนเซิร์ฟเวอร์ และดูภาพรวมผ่านแดชบอร์ดที่ดูเป็นระบบ มีโมเดล 3 มิติจำลองโรงเรือน
ผู้ใช้: ผู้ปลูก/ผู้ดูแล (แอดมิน) และคนอื่นที่ได้ลิงก์ดูแดชบอร์ด

## 2. ขอบเขต
**ทำ**
- หน้า **Login** สำหรับแอดมิน **[คุณเลือก]**
- หน้า **จัดการ (CRUD ครบ: สร้าง/ดู/แก้/ลบ)** ต้อง login **[คุณเลือก]**:
  - **สถานี** (ชื่อ, รายละเอียด, RFID UID, ตำแหน่งบนแผนผัง map_x/map_y, ลำดับเส้นทาง, เปิด/ปิดใช้งาน, ชนิดผัก)
  - **ชนิดผัก** (ชื่อ, label อาการ, prompt, เกณฑ์/หมายเหตุ)
  - **ล็อตผัก** — วันที่ปลูก / วันที่เก็บเกี่ยว / สถานี / ชนิดผัก / หมายเหตุ **[คุณเลือก]**
  - **API key ของ AI** (Claude, GPT, Gemini, Qwen, DeepSeek) + เลือกผู้ให้บริการ/รุ่น/base URL ที่ใช้งาน **[คุณเลือก]**
  - **Device key ของ ESP32** (สร้าง/เพิกถอน) **[ผมเลือก]** — "API key ต่าง ๆ" ตีความว่ารวมกุญแจของอุปกรณ์ด้วย
  - ผู้ดูแล (เปลี่ยนรหัสผ่าน, เพิ่ม/ลบแอดมิน) และบันทึกการเปลี่ยนแปลง (audit log)
- **แดชบอร์ดและกราฟ เข้าดูได้โดยไม่ต้อง login** **[คุณเลือก]**
- **แสดงผล 3 มิติแบบจำลองโรงเรือน** ที่ผักโตตามอายุล็อตและเปลี่ยนสีตามสถานะ **[คุณเลือก]**
- ดีไซน์: สไตล์ "ห้องควบคุมปฏิบัติการ" โทนเข้ม — ระบบออกแบบเก็บที่ `design-system/nexxa/MASTER.md` (สร้างด้วย ui-ux-pro-max)
- โหมดข้อมูลตัวอย่าง (demo) จำลองฤดูปลูก 100 วัน เพื่อให้แดชบอร์ดไม่ว่างก่อนมีข้อมูลจริง **[ผมเลือก]**

**ไม่ทำ (ในแผนนี้)**: รายงานสรุปและถามตอบด้วย AI, แจ้งเตือน Telegram, เฟิร์มแวร์ ESP32, ระบบหลายบทบาท (มีแค่แอดมิน), แอปมือถือ, แสดงรูปใบผักสู่สาธารณะ

**ล้มเหลวแม้ทำงานได้**: key รั่ว (ปรากฏในหน้าเว็บ/log/ฐานข้อมูลแบบอ่านออก), แดชบอร์ดสาธารณะเปิดเผยข้อมูลที่ไม่ตั้งใจ (รูป, หมายเหตุดิบ, key), 3D ทำให้เครื่องเก่าค้าง, ข้อมูลตัวอย่างปนกับข้อมูลจริง

## 3. แนวทางที่พิจารณา
| | แนวทาง | ข้อดี | ข้อเสีย |
|---|---|---|---|
| **A** | **Jinja2 สร้างหน้าที่ฝั่งเซิร์ฟเวอร์ + JavaScript ธรรมดา + ไลบรารี three.js/Chart.js แบบเก็บไว้ในโปรเจกต์** | ไม่มีขั้นตอน build, ขึ้น hosting ฟรีง่าย, ใช้ FastAPI เดิม | JS ฝั่งหน้าต้องเขียนเอง |
| B | แยกเป็น SPA (React/Vite) | UI ยืดหยุ่น | ต้อง build, ซับซ้อน, hosting ฟรีลำบากกว่า |
| C | HTMX + เซิร์ฟเวอร์ | JS น้อย | ไม่ช่วยงาน 3D/กราฟ, เพิ่มแนวทางใหม่ |

**แนะนำ A [ผมเลือก]** — ไลบรารี (three.js 0.185.1 ตามที่เครื่องมือค้นดีไซน์ระบุว่าตรวจแล้ว, Chart.js) ดาวน์โหลดมาเก็บใน `server/static/vendor/` พร้อมเลขเวอร์ชันและไฟล์ใบอนุญาต ไม่พึ่ง CDN ตอนรัน (ฟอนต์ Google ยังโหลดจาก CDN มี fallback)

## 4. ข้อมูลและความปลอดภัย
**ตารางใหม่** `batches` (ล็อต), `daily_stats` (สรุปรายวันต่อสถานี/ล็อต — ใช้กับกราฟ), `admin_users`, `provider_keys` (key ของ AI), `device_keys`, `app_settings` (provider/รุ่น/base URL ที่เลือก, โหมด demo), `audit_log`
- **อายุผัก** คำนวณจากวันที่ปลูกของล็อตที่ผูกกับสถานี ณ เวลาถ่ายภาพ

**การเก็บความลับ**
- key ของ AI เข้ารหัสด้วย Fernet โดยใช้ `NEXXA_SECRET_KEY` จาก env (เพิ่ม dependency `cryptography`) **[ผมเลือก]**; ถ้าไม่ตั้ง `NEXXA_SECRET_KEY` หน้าจัดการ key ถูกปิดและบอกเหตุผล (ปิดไว้ก่อน ไม่เก็บแบบอ่านออก)
- หน้าเว็บไม่เคยแสดง key เต็ม: แสดงแค่ 4 ตัวท้ายและวันที่เพิ่ม; แก้ = วางค่าใหม่; ลบได้; ห้ามอยู่ใน log/audit log
- device key เก็บเป็นแฮช (แสดงค่าจริงครั้งเดียวตอนสร้าง) **[ผมเลือก]**; ตัวแปร `NEXXA_DEVICE_KEY` เดิมยังใช้เป็น fallback
- analyzer เลือก key: key ที่เปิดใช้ในฐานข้อมูลของ provider นั้นก่อน, ถ้าไม่มีใช้ env (พฤติกรรมเดิม) และ provider/รุ่น/base URL จากหน้าเว็บมาก่อน env

**Login** **[ผมเลือก]**: รหัสผ่านแฮชด้วย scrypt (stdlib), คุกกี้ session ลงลายมือชื่อ (HttpOnly, SameSite=Lax, Secure เมื่อเป็น HTTPS, หมดอายุ), CSRF token ทุกการแก้ไข, จำกัดจำนวนครั้งล็อกอินผิดต่อ IP/ผู้ใช้, แอดมินคนแรกสร้างผ่านคำสั่ง `python -m app.create_admin` หรือ env ตอนเริ่ม

**ข้อมูลสาธารณะ** **[ผมเลือก]**: API `/api/public/*` อ่านอย่างเดียว คืนเฉพาะตัวเลขสรุป สถานะสถานี และชื่อสถานี/ผัก — **ไม่มีรูปภาพ ไม่มี note ดิบ ไม่มี key ไม่มี UID ของแท็ก**; ภาพจริงดูได้เมื่อ login; มีแคชสั้น ๆ และจำกัดอัตราเพื่อกันถูกยิงถล่ม

## 5. หน้าและพฤติกรรม
| หน้า | เข้าถึง | เนื้อหา |
|---|---|---|
| `/` แดชบอร์ด | สาธารณะ | การ์ดตัวเลข (สถานีใช้งาน, อัตราผิดปกติวันนี้, ภาพรอตรวจ, ล็อตใกล้เก็บเกี่ยว), **โมเดล 3 มิติโรงเรือน** (คลิกสถานีเพื่อดูรายละเอียด), กิจกรรมล่าสุด, ป้ายระบุเวลาอัปเดตข้อมูลล่าสุดและสถานะเก่า/สด |
| `/trends` กราฟ | สาธารณะ | เส้นแนวโน้มอาการต่อสถานี/ล็อต, เทียบล็อตอายุเท่ากัน, อัตราภาพถูกปฏิเสธ, ตัวกรองช่วงวัน; กราฟทุกอันมีตารางข้อมูลสำรอง |
| `/login` | สาธารณะ | ฟอร์มเข้าสู่ระบบ |
| `/admin/...` | ต้อง login | รายการ + ฟอร์มสร้าง/แก้ไข/ลบ ของ สถานี, ชนิดผัก, ล็อต, key AI, device key, การตั้งค่า AI, ผู้ดูแล, audit log |

**3 มิติ [ผมเลือก]**: โรงเรือนมีโครงและผ้ามุ้งโปร่งแสง แถวผักต่อสถานี (instanced mesh) ขนาดต้นผักโตตามอายุของล็อต สีตามสถานะล่าสุด (ปกติ/เหลือง/น้ำตาล/รอตรวจ) พร้อมไอคอนและป้ายข้อความ ไม่ใช้สีอย่างเดียว; หมุน/ซูมได้ (OrbitControls), หยุดเมื่อแท็บถูกซ่อน, จำกัด pixel ratio, เคารพ reduced-motion, ถ้า WebGL ใช้ไม่ได้ให้ใช้แผนผัง 2 มิติแทน
**กราฟ [ผมเลือก]**: Chart.js เส้นหลายเส้นใช้ทั้งสีและลายเส้น ชื่อเส้นกำกับตรง ๆ; ข้อมูลเกิน 1,000 จุดรวมเป็นรายวัน/รายสัปดาห์ก่อนส่ง
**ภาษา**: ส่วนติดต่อเป็นภาษาไทยเป็นหลัก **[ผมเลือก]** ตัวเลขและศัพท์เทคนิคตามเดิม
**ดีไซน์**: โทนเข้ม สไตล์ glassmorphism บนพื้น #0F172A เน้นสีเขียว #22C55E (ใช้โทเคนจาก MASTER.md), ฟอนต์ Plus Jakarta Sans + ฟอนต์ไทย (Noto Sans Thai) เป็น fallback, คอนทราสต์ ≥ 4.5:1, โฟกัสเห็นชัด, รองรับ 375/768/1024/1440px

## 6. ลำดับการสร้าง
1. ฐานข้อมูล/โมเดลใหม่ + บริการความลับ (เข้ารหัส key, แฮช)
2. Login/session/CSRF/สร้างแอดมิน
3. โครงเว็บ + ระบบดีไซน์ (เลย์เอาต์, CSS tokens, คอมโพเนนต์ฟอร์ม/ตาราง)
4. CRUD: สถานี, ชนิดผัก, ล็อต
5. จัดการ key AI/Device key/การตั้งค่า AI + เชื่อมกับ analyzer และการตรวจ device key
6. สรุปรายวัน (`daily_stats`) + API สาธารณะ
7. แดชบอร์ด + กราฟ
8. โมเดล 3 มิติ
9. ข้อมูลตัวอย่าง 100 วัน + เทสต์ทั้งระบบ (ความปลอดภัย, สิทธิ์เข้าถึง, โหลด)

## 7. ที่เหลือให้ผู้สร้างตัดสิน
ชื่อ route ย่อย, โครงไฟล์แม่แบบ, รายละเอียดสีของ 3 มิติ, ขนาดโมเดลต้นผัก (รูปทรงเรียบง่ายสร้างจากโค้ดไม่ต้องใช้ไฟล์โมเดล)

## 8. ความเสี่ยงที่รู้อยู่แล้ว
- เก็บ API key ที่เข้ารหัสได้ ไม่ได้ปลอดภัยเท่ากับไม่เก็บ: ถ้า `NEXXA_SECRET_KEY` หายหรือรั่วพร้อมฐานข้อมูล key ก็รั่ว (ทางเลือกที่ปลอดภัยกว่าคือใช้ env เท่านั้น)
- แดชบอร์ดสาธารณะ = ใครมีลิงก์ก็เห็นสถานะโรงเรือน (ไม่มีรูป/ความลับ)
- hosting ฟรีหลับ/ล้างดิสก์: ใช้ฐานข้อมูลภายนอกตามที่ตกลงไว้
- เว็บยังไม่ได้ทดสอบกับเบราว์เซอร์จริงในเครื่องผม (ทำได้เฉพาะเทสต์ฝั่งเซิร์ฟเวอร์และเช็กโครงสร้าง) — การดูตาจริงต้องให้คุณเปิดเอง
